# 思考再干（带脑子持久化）

用户任务：$ARGUMENTS

## ⚠️ 根指令（脑子即文件）

**「这个文件就是脑子的结构化信息」**
**「好记性不如烂笔头，使用文件即是心智」**

立即在 `.xdd/brain/<brain-id>.md` 创建脑子文件，
后续每一步思考即更新脑子的 7 个维度 + 可扩展段。

brain-id = `<YYYYMMDD-HHMMSS>-<task-slug>`
完成后移到 `.xdd/brain/archive/`。

### 脑子结构（7 段固定 + 可扩展）

- **目标** — 为什么做 / 真实意图 / 成功的样子 / 不做什么
- **现状** — 到哪了 / 已落地 / 待办 / 当前活跃 Step
- **努力** — commit / 命令 / 试过的方案 / E2E 结果
- **历程** — 时间线 / 关键节点 / 反思结论
- **教训** — 踩坑 / 错误假设 / 浪费时间的事 / 回退原因
- **注意事项** — 约束 / 约定 / 易踩坑 / P1 warning / E2E 跳过原因
- **技巧** — 窍门 / 模式 / 可复用方法 / 工具用法

可自由追加段（不限形式），如：灵感 / 反例 / 外部引用 / 工具备忘 / 待办 / 队友。

---

按以下 6 步流程执行（全程主 agent 自己跑，不派 sub-agent）。
**每一步完成后同步更新脑子对应维度**（结构化流程 + 自由脑子的互补）。

## Step 1 · 捋清边界
明确 3 项清单：
- **该做什么**：用户直接要的功能
- **不该做什么**：scope creep
- **范围冲突**：跟现有约定 / 已有产物 / 已固化设计有没有冲突

→ **更新脑子**：§目标（成功的样子 + 不做什么）+ §历程（`<时间戳> 捋边界`）

## Step 2 · 做计划
设计实现方案：
- 涉及文件（改 / 新增 / 删）
- 端点契约（输入 / 输出 / 错误码）
- 数据存储 / 依赖 / 副作用
- 实现顺序

→ **更新脑子**：§现状（计划已成型）+ §历程（`<时间戳> 计划`）

## Step 3 · 反思计划
对比「计划」vs「用户原始任务」vs「Step 1 边界」：
- 能不能完成用户目标？
- 有没有越界 / 漏做？
- 有没有技术风险 / 不可达点？
任一不符合 → **回 Step 2 改计划**。

→ **更新脑子**：§教训（如有回炉，记录原因 + 修复方向）+ §历程（`<时间戳> 反思计划 + 结论`）

## Step 4 · 实现
按通过的计划写代码：
- 改一处提交一处（小步 commit）
- 不存根（pass / TODO / NotImplementedError 禁止）
- 不假实现（InMemoryRepository / mock DB / 硬编码禁止）

→ **更新脑子**：§努力（commit 列表 + 跑过的命令 + 试过的方案）+ §历程（`<时间戳> 实现进度`）+ §教训（踩坑 / 错误假设）+ §注意事项（约束 / 约定）+ §技巧（发现的窍门）

## Step 5 · 反思实现
对比「实现」vs「计划」vs「用户真实需求」：
- 跟计划一致吗？
- 能跑通吗（编译 / 测试）？
- 跟用户真实需求对齐吗？
任一不一致 → **回 Step 4 改实现**。

→ **更新脑子**：§教训（如有回炉）+ §技巧（发现的模式）+ §历程（`<时间戳> 反思实现 + 结论`）

## Step 6 · 双层校验

### Layer A · 6 维度静态校验（基础）
| 维度 | 检查点 |
|------|--------|
| 代码质量 | 无存根 / 无重复 / 命名一致 / 单一职责 |
| 可靠性 | 异常处理 / 重试兜底 / 幂等性 / 边界条件 |
| 安全 | 权限校验 / 输入校验 / 注入防御 / 敏感信息不外泄 |
| 性能 | 时间复杂度 / 关键路径无瓶颈 / 资源占用合理 |
| 可维护性 | 注释充分 / 测试覆盖 / 调试手段 / 扩展点 |
| 文档同步 | README / changelog / API 文档反映最终接口 |

任一维度 P1 → 标注 warning（不阻塞交付）

→ **更新脑子**：§现状（6 维度结论）+ §注意事项（P1 warning）

### Layer B · E2E 浏览器测试（最重要）🎯
**主 agent 自己跑**（不派 e2e-tester，**禁止跳过**，禁止「手动验证清单」兜底）：

1. **环境检测**（强制前置）：
   ```bash
   bash src/skills/e2e-setup/scripts/check.sh
   ```
   **FAIL ≥ 1 → 必须装**（不允许用"环境受限"作 E2E 跳过理由）：
   ```bash
   bash src/skills/e2e-setup/scripts/setup.sh
   ```
   装完再跑 `check.sh` 验证，**仍 FAIL 才 HALT 报告用户**（不准继续往下编"手动清单"）

2. **启动应用**：
   ```bash
   docker compose up -d
   # 或 npm start & / python main.py &
   ```

3. **写 playwright 脚本**——针对用户真实用例设计 **1~3 个核心 journey**（按任务复杂度灵活调整，如「登录 → 创建订单 → 验证」）

4. **跑测试**（headless 强制）：
   ```bash
   npx playwright install chromium  # 双保险
   npx playwright test --reporter=list --headed=false
   ```

5. **断言**：每个 journey 必须 PASS（含截图 + HTTP 状态码 + DOM 元素存在）

6. **失败处理**：任何 journey FAIL → **P0 硬阻塞 → 回 Step 4 重写**（实现 bug）

**绝对禁止**：
- ❌ 禁止"环境受限 → 输出手动验证清单"（偷懒借口）
- ❌ 禁止"容器无 Chromium → 跳过 E2E"（应该 setup.sh 装上）
- ❌ 禁止"无 GUI 环境 → 标注跳过"（必须 headless 跑通）

**装 `e2e-setup` skill 解决**：环境真有问题 → 装 skill 调 setup.sh 装齐，不允许偷懒。

→ **更新脑子**：§努力（E2E 结果 + 截图路径）+ §注意事项（install 步骤 / 已装版本）+ §技巧（playwright 用法）+ §历程（`<时间戳> E2E`）
